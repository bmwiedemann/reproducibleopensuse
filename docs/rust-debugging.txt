Here is my write-up on how to debug reproducible-builds in rust

stracebuild + autoprovenance are usually not useful for similar reason as in java+python. Because one big build process produces a single binary.

autoclassify rarely gives insight - none of the tweaks help with random HashMap/HashSet order.

rust enables local-LTO by default that adds large amounts of noise in binary diffs for a single bit of variation. Disable it if possible. export RUSTFLAGS='-C lto=off'

build-root diffs are also noisy from timestamps and hashes. Sometimes one can find good pointers in there.

We build without internet, so large vendor tarballs are used to keep crates. These can still have buggy versions of i18n and other parts we fixed earlier.
So before starting a search, it would be good to check that known fixes are included. How to do that efficiently?

Builds usually take many minutes even on multi-core machines. This means iteration cycles are slow.

A normal test could use
    parallelism2=6 parallelism=7 rbk

and once other issues are resolved, do a harder test with
    debuginfo="--debuginfo" rbk
